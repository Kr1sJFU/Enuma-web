# ENUMA research website prototype

The repository root is a self-contained static site, published by GitHub Pages from the `main` branch. The homepage is video-first: the selected eight-step knight sequence ends on the moving paper teaser's mosaic, then the full ENUMA demo film, six interactive cases in a three-column, two-row grid, five horizontally browsable capability sections (Ref2Vid, Text Event, Ref Event, Interaction, Embodied), concise paper context, and a link to the separate ENUMA-Bench page. The benchmark remains a layout preview until the team supplies final scores and matched outputs.

Open `index.html` for the homepage and `benchmark/index.html` for the benchmark page. The site does not run live model inference; every video is a prerecorded ENUMA output. The hero follows ringworld → autumn celestial → tree kingdom → desert temple → mingjie → zigurat → stone lion → paper-teaser mosaic. The stone-lion clip ends at native frame 79 and the teaser starts with matching frame 80, then holds the finished mosaic; the hero button replays the sequence. The film is loaded only when played. All five capability sections use the same large 16:9 card layout, with arrow buttons, keyboard arrows, and touch scrolling; they currently contain 16 Ref2Vid (8 long, 8 short), 16 Text Event (8 long, 8 short), 8 Ref Event, 8 Interaction, and 8 Embodied cases. Interaction uses Take a Book (16 s), Magic Box, Wipe the Mirror, Release the Car, Stir the Chocolate, Wipe the Counter, Open the Door, and Drive the Car. Previews load only when visible, and full clips open on click. Long Ref2Vid and Text Event clips use 8-second previews while preserving the complete 30-second outputs in the player. Ref2Vid's long row uses 0264, 0412, 0256, 0243, 0825, 0679, 0757, and 0988; its short row uses 1, 2, 5, 7, 8, 15, 16, and 19. Text Event's long row currently uses cases 16, 0152, 0558, 0584, 0601, 0627, 0756, and 0131; cases 02, 0136, 0352, and 0559 are excluded. The eight short Text Event cases include a continuous 10–18 second extract of the 30-second lighthouse meteor source. Ref2Vid shows paired character and scene input images; Ref Event shows a starting frame and an event reference. Their reference thumbnails open the source-resolution image, with controls to switch between the pair. Obsidian Portal and Drawbridge / Dragon are four-turn experiences; Fireball / Brazier, Car Wash, and Residential Street are three-turn experiences, all copied from `video_tobe_concated/*/edit/interactive/`. Their numbered timelines let viewers replay any turn. Plush Cow plays the common event and then branches into Pat, Lift, or Drag, returning to the same decision frame between outcomes.

`prepare_media.py` reproduces the added web-sized event and interactive preview videos, their posters, and the copies of the turn-based pages. It also encodes web copies of the unusually high-bitrate Fireball / Brazier and Residential Street interactive masters at their original 720p resolution and frame rate, retaining the turn timing; the source masters remain untouched. `prepare_hero_media.py` reproduces the selected knight clips and teaser ending; `prepare_feature_media.py` reproduces the full-film and cow-event web versions. `prepare_capability_media.py` reproduces the Ref2Vid, Text Event, Ref Event, Interaction, and Embodied clips, event previews, and matched inputs. Ref Event uses new cases 1–3 and 8-second cases 1, 3, 6, 7, and 9. The three new Ref Event cases use the user's `-ezremove` / `-ez` watermark-cleaned videos with only the translucent I key restored by `RefEvent/edit/restore_i_key.py`; their posters and start-frame thumbnails come from these versions. The Stained Glass and Palace → Cyberpunk short Text Event cards use the user's `-ezremove` watermark-cleaned versions. Other website videos use their source materials without replacement control graphics. The full Demo uses the original `enuma_demo_current_v6_stable.mp4` master. New case 2's reference image was recreated from its output video and is marked as such on the page. The original research media is never modified. `media-manifest.json` records the source for each website asset. Additional cases can be added as cards inside each capability carousel; its counter, progress indicator, and page controls adapt automatically.

## GitHub Pages compatibility

The site lives at the repository root, like iMontage-web, and is published at https://kr1sjfu.github.io/Enuma-web/ with **Settings → Pages → Deploy from a branch → `main` / `(root)`**. Every push to `main` redeploys automatically, so push only release-ready content. The root `.nojekyll` makes GitHub serve the files as-is. The site uses relative local URLs, so it works under any base path. The build scripts and docs in the root are published too; they contain no private material.

Run `python3 verify_github_pages.py` before release. It checks the committed files only (what a branch deploy publishes): the site root, link and filename case, anchor targets, dynamically referenced videos and full-size references, clickable turn selectors, symlinks, and GitHub's site/file size limits. The current artifact is about 433 MB; every video is H.264/yuv420p MP4, and the largest file is the 36.8 MB Residential Street web copy. The hero has no eager video source on narrow screens, reduced-motion devices, or known slow/data-saving connections; its poster appears until playback is requested. On desktop, at most two visible card previews play at once; on narrow screens or known slow/data-saving connections, cards use posters until opened. Full capability clips and the research film load on click. Interactive pages preload only video metadata, using MP4 files with front-loaded metadata for progressive playback. GitHub Pages' published-site limit is 1 GB, with a 100 GB/month soft bandwidth limit; if traffic grows substantially, the video bandwidth should be reviewed. The large demo files exceed GitHub's 25 MiB browser-upload limit, so upload this repository with Git push rather than dragging all files into GitHub's web uploader.

The current website is a work in progress: copy is still pending, and the benchmark page is a layout preview.
